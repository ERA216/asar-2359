# Награды ASAR: состояние интеграции

Проверено 10 октября 2026 года для iDos Title `KJ56QZ5E` (Asar). PROD-конфигурация содержит `Currency.CryptoCurrencies.Main`: Solana mint `BHdDPbwbKW4XKsxhvi9zEbeWtEjWsvA9RFh9vZPLidos`, **6 decimals**. Публичный RPC подтвердил существование mint в **Solana mainnet**; в Devnet этой записи нет. В DEV iDos криптовалюта `Main` пока отсутствует. Подключённый MCP теперь имеет `config:read`, `config:write`, `cloudcode:write`, `build:write` только для Asar и его DEV-версии.

## Что проверено

- `server-reward-verifier.js` повторно строит карту по seed, проверяет каждый шаг, стены, три части, дедлайн, принтер и охранника. Предел: 1 ASAR за карту до уровня 15, затем 2. Локальный тест охватывает уровни 1, 10, 14, 15, 20, 21, 25 и 40: `node server-reward-verifier-test.js`.
- В DEV опубликована ревизия Cloud Code 7 из `idos-cloudcode-dev.bundle.js`. `asarDevStart` выдаёт seed и разрешённый уровень из защищённого состояния iDos. `asarDevFinish` проверяет маршрут и отклоняет повторную отправку завершённого раунда. Реальный тест `npm run test:cloudcode:dev` прошёл на уровне 1: незавершённый маршрут отвергнут, победный принят, повтор отвергнут.
- Это **только прототип проверки**. Он возвращает `rewardPreview`, но всегда `granted: false`; ресурсов не начисляет. Рабочая игра не вызывает эти обработчики. В PROD Cloud Code не опубликован и выплаты не включены.

## Что осталось для настоящих токенов

1. Связать вход в iDos с подписью Solana-кошелька. В PROD `Blockchain.WalletLogin.Enabled=false`. Во встроенной версии iDos нельзя полагаться на прямой доступ к Phantom из iframe; нужен штатный `loginWithWalletViaPlatform` или проверенный прямой поток для отдельного сайта. Один адрес кошелька из браузера не доказывает владения.
2. Подключить серверный раунд к игре без изменения правил карты. Клиент должен отправлять маршрут, а сервер — выдавать seed и уровень. Текущий локальный `?level=N` и `localStorage` нельзя принимать как право на выплату.
3. Учесть расходники и их серверное владение. Сейчас верификатор специально принимает только обычный маршрут; ключ, дополнительные ходы и термокружка должны проверяться отдельно. Победа с предметами не должна молча выдавать токен.
4. Подтвердить поддерживаемую операцию **обеспеченного** начисления `Main`, её точный формат, атомарную идемпотентность и запас ASAR в пуле наград игроков. Панель iDos поясняет, что крипто-награды выплачиваются из этого пула; возможность добирать недостачу из доли разработчика выключена. Метод `server.ApplyResourceOperation` существует, но доступные инструкции не описывают сигнатуру; безопасные пустые вызовы в DEV вернули `Reason is required`. PROD-настройка `CryptoRewardsFromDeveloperShare=false`, `CryptoIouForScriptsAndAI=false`; при недостатке для Cloud Code будет отказ, а выдавать `Main_IOU` вместо ASAR нельзя. Последовательная защита от повтора в DEV-прототипе ещё не доказывает безопасность при параллельных запросах. Нельзя подключать mainnet mint к DEV для пробных выплат реальных токенов.
5. Проверить в DEV реальную подпись, кошелёк/гостя, уровни 14/15/21+, победу/поражение, повторы и конкурирующие запросы, запас токенов, покупку/использование предметов и фактический вывод. После этого включать PROD и обновлять публичную сборку.

Локальные монеты в `localStorage` остаются игровыми и не конвертируются в ASAR по заявлению браузера. Наличие записи токена в конфигурации ещё не подтверждает доступный для выплат запас или фактическое зачисление в Solana.
