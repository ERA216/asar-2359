# Награды ASAR: состояние интеграции

Проверено 10 октября 2026 года для iDos Title `KJ56QZ5E` (Asar). В настройках есть криптовалюта `Main` с адресом Solana `BHdDPbwbKW4XKsxhvi9zEbeWtEjWsvA9RFh9vZPLidos` и **6 decimals**. Локальные монеты игры в `localStorage` не являются ASAR и не должны обмениваться на ASAR по заявлению браузера.

`server-reward-verifier.js` — отдельная чистая проверка результата. Она заново строит карту по серверному seed, проверяет каждый шаг, стены, сбор всех трёх частей, дедлайн, принтер и охранника; возвращает размер награды: 1 для уровней 1–14, 2 с уровня 15. Она не подключена к клиентской выдаче, не меняет игру и не переводит токены. Запуск проверки: `node server-reward-verifier-test.js`.

Для запуска настоящих наград нужны следующие связанные изменения:

1. Включить в iDos аутентификацию, связанную с кошельком, и выяснить поддерживаемый способ входа из встроенной страницы. Один лишь адрес из Phantom в браузере не доказывает владение кошельком серверу iDos. Гость получает 0.
2. Сервер выдаёт seed, идентификатор раунда и разрешённый уровень из защищённого состояния игрока. `?level=N` и сохранение браузера не дают права на награду.
3. Клиент сообщает последовательность ходов; сервер проверяет её и отклоняет повторный результат. Права на использование ключа, термокружки и дополнительных ходов должны учитываться серверным инвентарём до того, как эти раунды станут пригодны для выплаты. Текущий проверяющий модуль принимает обычные прохождения без расходников.
4. Сервер хранит атомарный журнал выдачи по аккаунту и карте и использует подтверждённый механизм iDos для **обеспеченной** выдачи `Main`. При ошибке ответа повторный запрос с тем же идентификатором не должен выдавать токены снова. Нужно проверить источник запаса токенов и способ зачисления игроку в iDos; локальное изменение числа монет и необеспеченный `Main_IOU` не подходят.
5. После проверки на DEV отдельно протестировать реальную подпись кошелька, победу, поражение, повторную отправку, смену кошелька, уровень 14/15, покупку и использование предметов. Только затем включать в PROD и обновлять публичную сборку.

Сейчас в подключённом MCP разрешены `config:read` и `build:write` для Title и DEV. Изменять Cloud Code, правила наград и вход через кошелёк этим подключением нельзя. В DEV и PROD Cloud Code не опубликован, а `Blockchain.WalletLogin.Enabled=false`. Публикация или настройка выплаты пока не выполнялась.
